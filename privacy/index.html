Privacy policy

Axl Lens Editor

Effective date: 31 October 2026

This policy describes the current private macOS Axl Lens Editor project operated by Axl Hazarika and this informational website. The app is developed for the developer’s own personal use. It is not offered to the public through this website.

1. Media and editing data on the Mac

When a file is imported, the local companion service creates a working import copy. The workspace can contain original media copies, prepared images, video frames, thumbnails, previews, catalogue records, edit recipes, presets, project files, diagnostic reports and rendered outputs. Original media and imported copies may include embedded camera, location or other metadata.

The app’s core import, source preparation, catalogue and export workflow operates on the Mac. A native window communicates with a companion service on the same machine. The app does not provide an app-operated public media storage service, user account system, messaging, cloud synchronisation or automatic social publishing.

The current Camera Kit rendering stage uses 8-bit SDR working media. Keeping a RAW or HDR original separately does not mean that an edited export preserves the original dynamic range or precision.

2. Snap Camera Kit and Lens services

The Camera Kit integration uses Snap’s SDK and network services for authorisation, configuration, Lens assets and related functionality. The SDK can transmit technical, usage and performance events, including SDK and software versions, device or operating-system information, locale, app origin, connectivity, session identifiers, Lens activity, downloads and errors. Depending on Snap’s configuration, it can also store a generated vendor identifier in browser storage.

Lenses can analyse image features, including facial landmarks, to render an effect. The app does not provide an identity-matching feature. Some Lens functionality can make additional network requests, subject to SDK controls and the selected Lens. This policy does not promise that every Lens or SDK operation is entirely offline or that all network processing is limited to a single service.

Snap controls its SDK legal notice and remembered acceptance. Where required by its configuration, Camera Kit can display Snap’s own notice when a Lens is applied. SDK services may initialise before that notice appears.

Snap’s handling and retention of data are described in its Privacy Policy and Camera Kit Terms. The developer does not control Snap’s retention periods.

3. File access, browser storage and permissions

File import and export use files and destinations selected on the Mac. The embedded browser can retain website data and SDK-managed storage between sessions. Local import copies, prepared media and catalogue records are stored separately from that browser data.

The imported-file editing workflow does not require the user to sign into an app-operated account. The Camera Kit connection uses the developer’s application credentials. Separate experimental local workflows may use a camera or virtual-camera renderer and their own macOS permissions. No location-based app feature is configured.

4. Retention and deletion

Imported copies, catalogue records, recipes, previews, diagnostic files and outputs can remain in local working storage until they are removed. Some preview caches are bounded and may be evicted automatically; this is not a promise that all app data is deleted automatically.

Closing the window, stopping a render or discarding a session does not necessarily delete its files. Removing an item from a catalogue also should not be assumed to remove every associated media copy. Use available cleanup actions or remove the relevant local workspace files when they are no longer needed. Saved exports and backups remain in their chosen locations until deleted separately.

Clearing embedded-browser website data is separate from deleting media and catalogue storage. Because the app’s working media is stored locally, the developer cannot remotely remove copies from another device. Contact the developer if help locating relevant app storage is needed.

5. Sharing and security

The app provides local exports and downloadable project or preset files. Sharing those files through another service is a separate user action governed by that service’s policies. Exported files and preserved originals may contain personal information or metadata.

The developer has not added an independent advertising or marketing analytics service to the editor or this website. This does not disable or replace the SDK telemetry described above. App credentials, media and working files should remain protected on the Mac and should not be included in public support posts.

6. This GitHub Pages website

This site contains static project information and this policy. It has no app login, media upload form, advertising scripts or site-specific analytics scripts. GitHub hosts the site and processes hosting and security information. GitHub states that it logs and stores visitors’ IP addresses for security purposes, whether or not they are signed into GitHub.

See GitHub Pages data collection and GitHub’s Privacy Statement. Following links to Snap, GitHub or the developer’s portfolio is subject to those websites’ own policies.

7. Changes and availability

This policy describes a private development project. Public distribution, new services or material changes to data handling would require an updated policy and any applicable notices. The effective date at the top identifies this version. The website and policy do not indicate Camera Kit production approval.
